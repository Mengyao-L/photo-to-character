# 照片转极简角色插画

把照片中的真实特征提炼为适合软件插图、表情包和后续动画制作的二维角色。核心路径：照片 → 身份特征 → 几何概括 → 实线主轮廓 → 闭合色块 → 动画友好结构。

## 输入与参考优先级

- 先查看实际照片和用户提供的手稿、标准插画；不要仅凭文件名推测画面。照片负责身份与姿态，已认可的插画负责造型和画风。
- 当前用户要求优先于本规范。明确区分风格参考、身份参考、姿态参考；冲突时优先保留已认可角色的固定特征，只从新照片提取本次动作。
- 有照片即可开始，不强制要求先填表。缺少照片时，请用户提供；不能看见的旧附件不能当作已读取的参考。
- 默认生成单张、保留原姿态和表情、简洁浅色背景。透明背景、尺寸、文字和动作数量按用户要求；没有要求时不要擅自生成完整动画或一批变体。

## 固定画风

1. **轮廓概括。** 用圆润、简单、连贯的几何形抓住头、躯干、耳朵、四肢和尾巴。毛茸茸感来自整体蓬松外形及少数大的轮廓起伏，不画逐根毛发、密集锯齿或碎线。
2. **柔和实线。** 主结构使用清晰连续的实线，转角柔和，线宽整体一致。默认深灰褐或协调的深色轮廓，避免粗黑边压过主体；内部线比外轮廓更少、更轻。参考图已有认可线色与线宽时沿用。
3. **大色块。** 使用少量、边界清晰、闭合的大面积纯色色块。将毛色和花纹概括成辨识度最高的区域，不照搬照片里的光斑、噪点和碎毛。无现有色板时建议约 4–7 个主体颜色，必要时为身份特征保留额外颜色；这只是起始建议。
4. **极简细节。** 保留耳形、脸型、眼形与间距、鼻口位置、主要花纹、尾巴形状等关键特征。舍弃非必要毛纹、皮肤纹理和衣物褶皱。眼睛简洁有神，避免复杂虹膜、多重高光和夸张日漫大眼。
5. **治愈比例。** 形状柔软，表情自然亲近。适度概括和圆润化，保持主体原有体态及角色比例，不自动改成巨大头部、极短四肢的通用萌宠。
6. **二维平涂。** 默认无渐变、无体积塑造；有用户要求时只加入极少、边界清晰的阴影色块。避免水彩晕染、纸张纹理、油画笔触、写实毛发、摄影光影、3D、毛绒玩具质感。
7. **便于动画。** 耳朵、眼睛、头身连接、爪子和尾巴要读得清楚。用简洁遮挡关系和稳定色块边界，避免装饰线与肢体粘连。保持原照片遮挡，不为“全身完整”凭空增加可见肢体。

## 角色一致性

首次使用时，从可见素材提取少量固定特征作为本次角色锚点，不虚构看不见的花纹。需要跨照片复用或角色表时，读取 [角色档案模板](references/character-bible.md)，在用户项目中保存独立档案；不要把私人照片或角色信息写回共享 Skill。

沿用已认可的头身比例、眼距、耳形、色板和花纹位置。左右以角色自身为准，镜像照片要特别检查。姿势、视角和表情可以变化，身份特征不能随之任意重设计。用户认可的标准插画是后续生成的视觉锚点；不要只依赖长对话中的文字记忆。

## 生成与检查

- 使用当前环境可用的图像生成或编辑能力；若环境提供 imagegen 技能，在执行图片生成时读取并遵守其工具用法。把实际照片和标准插画作为参考输入，并在提示中说明各自用途。
- 提示词包含：本次动作、身份锚点、固定画风、构图/背景/尺寸要求。明确“重新绘制为极简二维角色”，不要只要求“加卡通滤镜”。
- 没有图像工具时，交付完整可用提示词并明确尚未生成图片；不要把文字说明当作图片交付。
- 检查生成图的轮廓是否过于粗重、毛发是否碎化、颜色是否碎片化、五官/花纹是否漂移、肢体是否多出或融合，以及实际背景和裁切是否符合要求。
- 明显偏离时针对具体问题修订；不要无止境重抽。若两次针对性修订仍偏离，说明剩余问题并保留最佳结果，等待用户下一步选择。
- 对多姿态或动画相关请求，读取 [动作与资产规范](references/animation-assets.md)。

## 交付

优先展示生成结果，简要说明保留了哪些身份特征及任何未解决偏差。保存文件时同时保留实际使用的提示词与引用的角色档案版本，便于复用。

图片输出能力决定格式：仅在实际生成或检查到透明通道后称为透明 PNG；平面图片不是可编辑 SVG、PSD 分层或可播放动画。需要这些资产时分别制作、检查并据实标明完成范围。
